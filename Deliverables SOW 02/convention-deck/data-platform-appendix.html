01 EXECUTIVE SUMMARY

Four platforms are credible candidates for Gold's unified data layer. Each uses a different billing model, has a different operational profile, and demands a different team skill mix. Platform cost alone rarely determines the right choice — staffing is typically the largest single line item at medium and large scale, and platform selection directly drives required skill set and team size.

KEY ASSUMPTIONS
  • Workload mix: analytics / BI + data engineering / ETL with moderate ML
  • Concurrency: moderate (10–50 users / pipelines)
  • Region: US data centers (US East 1 / Azure US West 2 used as reference)
  • Pricing: list / pay-as-you-go unless commitment / reserved noted
  • Staffing: US national salary midpoints + ~25% benefits load

Three reference tiers are used throughout this analysis. Gold's profile (~400 US locations in scope, member transactions, app and web analytics, operational reporting) sits in the Medium tier — likely toward the lower end of the band given the US-only scope. TCO figures in this report should be read with that in mind: anchor expectations on the lower half of each Medium-tier range until ingestion and storage volumes are measured against actual workloads.

02 PLATFORMS EVALUATED
MICROSOFT FABRIC

Capacity-based platform unifying Spark notebooks, data pipelines, Lakehouse, Data Warehouse, Power BI reports, and real-time analytics under a single pooled allocation. Sold as an Azure SKU.

Best for: Microsoft / Azure-integrated organizations with significant Power BI investment.

DATABRICKS

Spark-native unified analytics platform spanning data engineering, data warehousing, ML, and streaming. Available on AWS, Azure, and GCP. Customer pays Databricks for the platform layer plus the underlying cloud provider for VM infrastructure.

Best for: ML / AI-heavy workloads, Spark-distributed processing, real-time streaming at scale.

SNOWFLAKE

Cloud-native SQL data platform with consumption-based credit billing. Auto-suspending virtual warehouses, automatic clustering, and a strong ecosystem of partner integrations. Available on AWS, Azure, and GCP.

Best for: Multi-cloud portability, SQL-first analytics, low operational overhead.

AWS REDSHIFT

AWS-native columnar data warehouse with two deployment models — Provisioned (fixed clusters, node-hour billing) and Serverless (RPU-hour, idle = $0). Decoupled compute and storage with RA3 nodes.

Best for: AWS-native organizations with steady, predictable analytical workloads.

03 HOW EACH PLATFORM BILLS

Understanding the billing unit is critical before comparing dollar amounts. The four platforms use entirely different models — comparing one calculator to another without normalizing units leads to material misestimation.

Snowflake Credits (per-second warehouse billing) · $2–$4 per credit by edition Compute + serverless features (Snowpipe, automatic clustering) Compressed storage · ~$23/TB-month
AWS Redshift Node-hours (Provisioned) or RPU-hours (Serverless) · ~$0.38/RPU-hour Compute only; managed storage billed separately Redshift Managed Storage · ~$24/TB-month
DISCOUNT MECHANICS
  • Fabric: Reserved 1-year ~41% savings vs. PAYG
  • Databricks: 20–40% off DBU commitments (annual / multi-year); stackable with cloud marketplace commits (AWS EDP, Azure MACC)
  • Snowflake: 20–30% off via Capacity Plans; 25–45% at high volume (100K+ credits/yr)
  • Redshift: 1-yr Reserved ~40% off · 3-yr Reserved up to ~75% off
BILLING NUANCES TO KNOW
  • Databricks: Pricing only the Databricks calculator routinely underestimates total spend by 50–200% — VM costs are the missing layer
  • Fabric: Below F64, Power BI consumers each need a Pro license (~$14/user/month); F64+ includes viewer licensing
  • Snowflake: Actual bills typically run 25–40% higher than warehouse-only estimates due to cloud services, automatic clustering, and egress
  • Redshift: Serverless idle = $0; Provisioned bills continuously

09 STRATEGIC CONSIDERATIONS

The right platform depends on which dimensions weigh most heavily for the organization. The framings below describe when each platform is materially advantaged — not which one Gold's should pick.

WHEN MICROSOFT FABRIC IS ADVANTAGED
  • Heavy existing Microsoft / Azure / M365 footprint
  • Active Azure Consumption Commitment (MACC) — Fabric draws down existing budget rather than creating new spend
  • Power BI is the BI tool of record — DirectLake mode and bundled viewer licenses (F64+) materially reduce cost vs. competitors
  • Existing analyst / engineer talent is in the Microsoft stack — fastest upskill path
  • Team size and complexity should be minimized (asset-light operating model)
WHEN DATABRICKS IS ADVANTAGED
  • ML / AI is core to product strategy (recommendations, personalization, churn prediction)
  • Spark-distributed processing is required at scale
  • Real-time streaming pipelines are central to the architecture
  • Organization is comfortable funding a specialized platform engineer from day one
  • Multi-cloud portability is a long-term requirement
WHEN SNOWFLAKE IS ADVANTAGED
  • Multi-cloud portability is a hard requirement
  • SQL-first analytics is the dominant workload
  • Operational simplicity is prized — auto-suspend, auto-scale, minimal admin
  • Analyst-led self-service is core to the data culture
  • BI tool is Tableau, Looker, or another non-Microsoft platform
WHEN AWS REDSHIFT IS ADVANTAGED
  • Organization is AWS-native and has an active EDP / commit
  • Workloads are steady, predictable, and SQL-centric
  • 3-year reserved commitments are acceptable for cost optimization
  • Existing AWS data engineering team is in place
  • Compute idle cost matters less than steady-state efficiency
FUTURE UPGRADE PATH — LAYERING DATABRICKS ON FABRIC

A pattern worth knowing: organizations that select Fabric as the analytics and data engineering foundation can later layer in Azure Databricks (sold through Azure Marketplace) for ML model training and advanced Spark workloads, reading directly from OneLake / Delta Lake. This avoids paying Databricks rates for workloads Fabric handles natively, while preserving the upgrade path as ML / AI maturity grows. It is not a binary choice.

10 DIRECTLAKE MODE — FABRIC-EXCLUSIVE

DirectLake is a Power BI semantic-model storage mode introduced with Fabric, enabling direct query of OneLake Parquet / Delta tables at near in-memory performance — without import refresh or DirectQuery latency. It is exclusive to Fabric.

WHY IT MATTERS
  • Eliminates the historic trade-off between import (fast, stale) and DirectQuery (live, slow)
  • Removes data duplication between the lakehouse and the semantic model
  • Reduces refresh time, model size, and compute cost on Power BI workloads
  • Materially advantages Fabric for organizations with significant Power BI investment
CAVEATS
  • Only works against OneLake-stored Delta tables — data must land in Fabric
  • Some advanced semantic-model features still require import or DirectQuery fallback
  • Still maturing as a feature; capability gap with import mode narrows release-by-release
11 OPEN QUESTIONS — NARROW THE RANGES

Answering 3–4 of these will reduce the budget and platform spread by an order of magnitude. The first three (cloud commitments, data volume, BI tool) move the needle the most.

  1. Data volume and growth rate — how many GB / TB stored today, and 12-month projection?
  2. Workload mix — what % of compute is batch ETL vs. interactive SQL vs. ML training / inference vs. streaming?
  3. Concurrency — how many simultaneous users / jobs at peak?
  4. Existing cloud commitments — active AWS EDP, Azure MACC, or Google CUD agreements?
  5. Compliance requirements — HIPAA, PCI-DSS, SOC 2 Type II, FedRAMP?
  6. BI tool — Power BI, Tableau, Looker, other?
  7. Data freshness — near-real-time (< 5 min) required, or hourly / daily acceptable?
  8. Team composition today — existing cloud engineers / DBAs / data engineers? Retraining vs. net-new?
  9. Multi-cloud or single-cloud — replicated across providers / regions?
  10. Contract term flexibility — PAYG for POC vs. 1–3 year reserved?
